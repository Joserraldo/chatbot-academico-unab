Decisiones

  • La tabla rag_documentos la crea n8n y se consulta con similitud coseno; no hay índice separado que pueda quedar desincronizado.
  • Si cambia el corpus, se vuelve a ejecutar 05 y el índice se publica al terminar la transacción.

El corpus es sintético y está marcado como tal; reproduce guías del CCD y del plan de estudios, no documentos oficiales sin publicar.

TEMA 2 · GUARDRAILS

Qué bloquea y qué oculta

Guardrail de entrada

Antes de llamar al LLM

  • Prompt injection: intentos de ignorar o cambiar las reglas del asistente.
  • Código de otro estudiante: solo se permite el código de la sesión; el resto se rechaza.
  • SQL y datos sensibles: consultas directas, credenciales o información privada.
  • Tema fuera de alcance: solo matrícula, avance, calendario, noticias y éxito académico.
  • Longitud: mensajes desproporcionados se cortan antes de procesarse.

Guardrail de salida

Antes de responder a la app

  • Oculta códigos de otros estudiantes y correos electrónicos.
  • Oculta errores técnicos, rutas y detalles internos.
  • Limita la longitud para mantener respuestas legibles.
  • Si hubo bloqueo, responde un mensaje seguro con intencion=bloqueado.

TEMA 2 · PROBLEMAS Y DECISIONES

Lo que salió mal y cómo lo resolvimos

Problema · cómputo

La EC2 no tiene GPU

Un modelo local de 7B no cabe en las instancias pequeñas de AWS Academy ni tendría latencia aceptable.

Aprendizaje: el LLM no necesita ejecutarse en la VM.

Decisión: LLM por API B.AI, qwen3.8-flash; el proveedor se cambia solo en .env.

Problema · embeddings

B.AI rechazó /v1/embeddings

El endpoint de embeddings no estaba disponible con la credencial; el RAG se quedaba sin vectores.

Aprendizaje: ingesta y consulta deben usar el mismo modelo.

Decisión: FastEmbed local en CPU, MiniLM multilingüe de 384 dimensiones, cacheado en un volumen.

Problema · dependencia externa

Supabase pausa el plan gratuito

Depender de una cuenta externa complicaba la réplica y la demo en el laboratorio.

Aprendizaje: menos servicios gestionados = demo más reproducible.

Decisión: PostgreSQL 16 + pgvector en la misma VM; el SQL es 100 % compatible con Supabase.

Problema · latencia

Una consulta superó los 90 s

El razonamiento extendido de Qwen alargaba la respuesta de historial en el emulador.

Aprendizaje: el razonamiento extendido no siempre compensa la latencia.

Decisión: desactivar el razonamiento en los nodos de chat y repetir el smoke test; la app recibió la respuesta.

Problema · credenciales

401 al embeber

La credencial de embeddings había quedado desactualizada tras rotar los secretos.

Aprendizaje: las credenciales también se tratan como configuración reproducible.

Decisión: corregir el .env y reimportar las credenciales renderizadas para n8n.

Problema · calendario

El Google Sheet no estaba publicado

El flujo dependía de un CSV de Google Sheets que aún no existía en la cuenta del equipo.

Aprendizaje: todo servicio externo necesita un plan B local.

Decisión: respaldo /calendario.csv desde PostgreSQL; el flujo acepta el Sheet cuando se publique.

TEMA 2 · CONCLUSIONES

Qué quedó funcionando y qué sigue

Conclusiones

  • El asistente responde las cuatro intenciones y bloquea los casos sensibles; se verificó de punta a punta en EC2, Android y Claude Code.
  • El RAG mantiene 20 fragmentos de 5 documentos y devuelve la fuente correcta para la pregunta por la insignia.
  • Los workflows quedaron como código reproducible con IDs fijos: se importan y publican sin ajustes manuales.
  • El MCP separa el razonamiento del dato: herramientas parametrizadas y un rol de solo lectura, reutilizable por otros clientes.
  • La app y la web comparten el mismo contrato JSON; la clave se ingresa enmascarada y la sesión conserva memoria.
Límites honestos: los datos de estudiantes son sintéticos, no hay autenticación institucional por estudiante y la clave del webhook es compartida. Es una demo académica, no un sistema en producción.
